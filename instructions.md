# Harmony Harness Demo

## Architecture workflow

For any non-trivial feature or system change, use skills/grill-with-docs/SKILL.md before implementation. It turns a loose request into explicit decisions grounded in the codebase.

Keep active scope and open questions in CONTEXT.md. Record consequential technical choices in docs/adr/, and keep docs/ARCHITECTURE.md current when boundaries or request flows change.

## Quality bar

Ship the smallest coherent change with clear ownership, failure behavior, observability, and rollback or migration notes where applicable.
